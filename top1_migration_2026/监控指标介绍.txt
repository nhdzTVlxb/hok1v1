监控指标介绍

一、环境指标

1. win_rate
含义：训练中最新模型一方的胜率。
怎么看：短时间波动正常，长期接近 0 或 1 都要小心。长期为 1 不一定代表真的学会了，可能是对手或红蓝镜像有问题。

2. self_tower_hp / enemy_tower_hp
含义：我方塔血量 / 敌方塔血量。
怎么看：如果两个值总是围绕 6000 对称、和为 12000，通常说明双方互相推塔或统计口径是零和。若 enemy_tower_hp 长期不下降，说明没有有效推塔。

3. frame
含义：每局持续帧数。
怎么看：帧数很短说明很快死亡或很快结束；帧数长期固定不变，可能是 train_test 截断、评估截断，或对局进入固定模式。

4. kill / death
含义：我方击杀数 / 死亡数。
怎么看：kill 长期为 0 且 death 有值，说明打架能力弱；kill 上升但不推塔，说明策略只会打架不会赢。

5. money_per_frame
含义：每帧经济收益。
怎么看：能补兵、刷野时会提高。若长期很低，说明不清线、不刷野、出泉水慢或行动停滞。

6. hurt_to_hero / hurt_by_hero
含义：我方对敌方英雄造成的每帧伤害 / 我方受到敌方英雄伤害。
怎么看：hurt_to_hero 上升说明开始打英雄；hurt_by_hero 远高于 hurt_to_hero，说明换血亏或走位差。

二、评估指标 common_ai

1. win_rate_common_ai
含义：对 common_ai 或评估对手时的胜率。
怎么看：比训练环境 win_rate 更能反映泛化，但如果 common_ai 行为异常，也不能完全相信。

2. self_tower_hp_common_ai / enemy_tower_hp_common_ai
含义：评估时双方塔血。
怎么看：如果 self_tower_hp_common_ai 一直 12000、enemy_tower_hp_common_ai 一直 0，可能评估对手很弱或镜像/配置异常。

3. frame_common_ai
含义：评估局持续帧数。
怎么看：固定直线通常说明评估流程或对局结果非常固定。

4. kill_common_ai / death_common_ai
含义：评估时击杀/死亡数。
怎么看：kill_common_ai 高但 enemy_tower_hp_common_ai 不变，说明会杀人但不一定会推塔。

5. money_per_frame_common_ai
含义：评估时每帧经济。
怎么看：用于判断是否稳定补兵、刷野、吃资源。

6. hurt_to_hero_common_ai / hurt_by_hero_common_ai
含义：评估时英雄伤害交换。
怎么看：hurt_to_hero 明显高于 hurt_by_hero，一般说明打架占优。

三、算法指标

1. reward
含义：平台展示的累积回报。
怎么看：如果长期为 0，可能是监控上报口径没接上，也可能是 reward 设计太稀疏。不能单独用它判断训练是否有效。

2. total_loss
含义：总损失。
怎么看：有轻微波动正常。完全不动可能说明样本太少、策略变化太小、梯度很弱或训练没真正进行。

3. value_loss
含义：价值网络损失。
怎么看：长期为 0 或不动，可能是 reward 信号太弱或 value 训练没吃到有效样本。

4. policy_loss
含义：策略网络损失。
怎么看：长期为 0 或不动，说明策略更新很弱。若剧烈震荡，可能学习率过大或 reward 太激进。

5. entropy_loss
含义：策略熵损失，反映探索程度。
怎么看：绝对值通常为负。逐渐接近 0 说明策略变确定；长期很低说明仍非常随机。

四、自定义基础奖励指标

1. diy_1 reward_sum
含义：训练采样侧的累计 reward。
怎么看：用于看 reward 是否真实产生。比平台 reward 更接近代码里的 reward_sum。

2. diy_2 hp_point_weight
含义：血量差相关奖励。
怎么看：正值说明换血/生存占优，负值说明经常被打亏。

3. diy_3 money_weight
含义：经济差相关奖励。
怎么看：上升说明补兵、刷野、吃资源有效。

4. diy_4 tower_hp_point_weight
含义：塔血差奖励。
怎么看：正向说明推塔或守塔占优。若长期不动，说明推塔行为弱。

5. diy_5 eval_hp_point_weight
含义：评估侧血量奖励。
怎么看：只在评估局有意义，用于判断对评估对手换血是否占优。

五、推塔与攻击诊断指标

1. diy_6 tower_damage
含义：敌方塔血下降总量，不区分是谁造成的。
怎么看：大于 0 说明敌塔确实在掉血。

2. diy_7 hero_tower_damage
含义：由我方英雄攻击造成的敌塔伤害。
怎么看：这是判断“智能体是否真正推塔”的核心指标。长期为 0 就说明没有有效打塔。

3. diy_8 safe_push_frames
含义：安全推塔窗口帧数。
条件大致是：敌方塔正在攻击我方小兵、敌方英雄不构成威胁、我方英雄能打到塔。
怎么看：如果这个值大于 0，说明环境中出现了安全推塔机会。

4. diy_9 safe_push_attack_frames
含义：安全推塔窗口内，我方选择攻击塔的帧数。
怎么看：如果 diy_8 大于 0 但 diy_9 为 0，说明有机会但没有打塔。

5. diy_10 tower_hit_frames
含义：命中塔或攻击目标为塔的帧数。
怎么看：能更直接看是否发生打塔行为。

6. diy_12 rune_pickups
含义：一局内吃到补血神符的次数。
怎么看：低血且安全时应逐渐非 0；长期为 0 说明神符路线或神符识别还要查。

7. diy_13 hit_per_1000
含义：每 1000 帧命中目标的次数。
怎么看：用于判断是否频繁产生有效攻击或技能命中。

9. diy_14 normal_attack_per_1000
含义：每 1000 帧普通攻击动作次数。
怎么看：太低说明不爱平 A；太高但无命中，可能目标距离/朝向/合法目标有问题。

10. diy_15 avg_attack_interval
含义：平均命中间隔，单位是帧。
怎么看：越低代表攻击节奏越密。过高说明输出不连续。

11. diy_16 monster_kills
含义：一局内由我方英雄击杀野怪/中立资源的个数。
怎么看：经济发育阶段应该逐渐上升；长期为 0 说明刷野目标、索引或奖励仍需检查。

12. diy_17 bad_fight_frames
含义：劣势接战帧数。大致统计敌方英雄可见且接近/正在打架时，我方血量明显低于敌方，或低血还继续接战的帧数。
怎么看：这个值越高，说明 agent 还不会判断“这波打不过”。修复后应逐渐下降；若很高且 death 上升，说明撤退/回塔/回城逻辑还不够。

13. diy_18 tower_target_legal_frames
含义：普攻选择敌塔作为 target=7 合法的帧数。
怎么看：如果大于 0，说明平台动作空间允许打塔。

14. diy_19 tower_target_action_frames
含义：实际选择普攻打塔 target=7 的帧数。
怎么看：如果 diy_18 大于 0 但 diy_19 为 0，说明策略/兜底没有正确选择打塔。

15. diy_20 tower_targeted_me_frames
含义：敌方塔正在攻击我方英雄的帧数。
怎么看：过高说明越塔或撤退不及时；安全推塔时这个值应该很低。

六、技能与野怪诊断指标

1. diy_21 skill1_actions
含义：1 技能释放次数。
怎么看：清线阶段应该逐渐非 0；如果长期为 0，说明技能 button 或 legal_action 仍有问题。

2. diy_22 skill2_actions
含义：2 技能释放次数。
怎么看：应主要出现在英雄交战时。非战斗时过高说明乱放。

3. diy_23 skill3_actions
含义：3 技能/大招释放次数。
怎么看：应主要在英雄交战时出现。长期为 0 说明大招逻辑或等级/合法性不足。

4. diy_24 skill_hit_frames
含义：技能命中帧数，统计 slot_type 为 1/2/3 的命中。
怎么看：释放技能但这个值不上升，说明技能没命中或字段映射仍需查。

5. diy_25 skill_hero_hit_frames
含义：技能命中敌方英雄的帧数。
怎么看：判断技能是否真正用于打英雄，尤其是大招是否有价值。

6. diy_26 monster_hit_frames
含义：命中野怪/中立资源的帧数。
怎么看：用于判断是否开始刷野或争抢中立资源。

七、常见判断组合

1. 有安全推塔机会但不推塔
看：diy_8 > 0，diy_18 > 0，但 diy_19、diy_7 仍为 0。
结论：动作选择没选塔，继续查 agent action 或模型是否更新。

2. 会推塔但被塔打死
看：diy_7 > 0，同时 diy_20 很高、death 上升。
结论：撤退逻辑或塔危险惩罚不够。

3. 会打架不会赢
看：kill/hurt_to_hero 上升，但 enemy_tower_hp 不下降、diy_7 为 0。
结论：需要继续加强安全推塔奖励和打塔兜底。

4. 会清线但不刷野
看：money_per_frame 一般，diy_26 长期为 0。
结论：野怪目标索引、野怪识别或争抢奖励还要查。

5. 技能乱放
看：diy_22/diy_23 上升，但 diy_25 不上升。
结论：2/3 技能没有用于英雄战斗，需要更强动作保护或负奖励。

6. 大招完全不用
看：英雄等级 >= 4 后，diy_23 仍为 0。
结论：大招 button/合法性/战斗窗口判断需要继续查。
